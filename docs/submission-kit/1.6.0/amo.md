   `pnpm release 1.6.0 --tag` (it refuses while a TODO is left)
   and push what it prints.
2. When the GitHub Release `v1.6.0` exists, run the **Publish to
   stores** workflow (version `1.6.0`) and approve it in the
   `store-publish` environment. It uploads `brreg-snap-1.6.0.zip`
   and `brreg-snap-source-1.6.0.zip` to AMO with the release notes
   and the reviewer notes below, then tags `amo-submission-1.6.0`.
3. Only if this release changed them: the listing text and the
   privacy policy (sections below) go up with the workflow's
   `amo_listing` input; screenshots and the icon stay manual, per

<!-- field: approval_notes -->
```text
A popup and sidebar company lookup for Norwegian users. No content
scripts; the only host it contacts is `data.brreg.no`, the public
API of the Norwegian Brønnøysund Register Centre.

Data collection: to find the company behind the current site, the
add-on sends data.brreg.no an organisation number found in the page
address or title or, if there is none, the site's registrable
domain (`dnb.no` for `nettbank.dnb.no`; subdomains are not sent,
except a site's own name on some known hosting platforms, such as
`firma.github.io`) and a name label derived from it. Search-box
text and text explicitly selected for a right-click lookup are sent
as a search (a selection: at most 100 characters, and only the
number when it holds exactly one valid organisation number). Hence
`data_collection_permissions` `required: ["browsingActivity"]`,
which Firefox 140+ shows in the install and update prompts. IP
addresses and reserved local names (localhost, single-label hosts,
.local, .lokal, .internal, .intern, .lan, .home.arpa, .priv) are
never sent. Nothing goes to the developer or any other party.

Lookups run on a click of the toolbar button, the sidebar, a
keyboard shortcut, a context-menu item or a search, and, only if the
user turns on "Auto-oppdater" and grants `tabs`, on every tab switch
or new page while a brreg-snap sidebar is open.

Firefox 115–139 ignore the declaration. There, each click lookup is
the direct result of one deliberate command on a clearly labelled
control, and the listing says what is sent (implicit consent under
the add-on policies). "Auto-oppdater" first shows its own disclosure
of what is sent and to whom; its «Slå på» button is the explicit
consent.

No API or host permission added since 1.1.0 (1.3.1 changed only the
data collection declaration, from `none` to `browsingActivity`).
Annual-report PDFs and announcements are ordinary user-clicked
links. A welcome page opens once on install, not on update, and
makes no network requests. Schibsted Grotesk is bundled locally (SIL
Open Font License, fonts/OFL.txt). "Rapporter feil treff" is a
mailto link and sends nothing itself.

To test: open https://www.dnb.no and click the toolbar button (the
popup shows DNB BANK ASA), then open the sidebar; "Auto-oppdater" in
its header asks for `tabs`.

Build: Vite's default minifier (Oxc); no source maps in the package.
The attached source zip is `git archive` of tag `v1.6.0`;
instructions in `BUILD.md` at the repo root. Reproduce with
`pnpm install --frozen-lockfile && pnpm package` on Node 24
(`.node-version`) and pnpm 12.10.1 (`packageManager`). The unzipped
package matches the CI build attached to the GitHub Release for
`v1.6.0`.

The listing privacy policy matches `PRIVACY.md`.
```

## What changed (CHANGELOG § [1.6.0])

For writing the release notes; not pasted anywhere.

> ### Added
>
> - Økonomi shows how the company has done over the last few years:
>   «Utvikling 2022–2024», driftsinntekter and årsresultat for up to
>   three years in aligned columns, with the unit once beside each label,
>   and a plain sentence under them («Driftsinntekter ned 26 %, høyest i
>   2024.») that also says when the result turned from profit to loss or
>   back. A sentence never claims more than the years on screen show. A
>   latest filing without figures still shows the years before it.
>
> ### Changed
>
> - A new logo: a blue ribbon tied in an overhand knot replaces the gold
>   «B», on the toolbar and store icons and at the head of the popup, the
>   panel and the welcome page.
> - The store name and short description say what you get for the
>   company behind the site you are on, instead of the bare «brreg-snap»
>   and «Slå opp norske bedrifter i Brønnøysundregistrene med ett klikk.»
> - A danger verdict is a field framed in thin red on a faint tint: a red
>   «✕ Alvorlig» kicker, then the sentence in large type with only the
>   key word in red.
> - When brreg can't be reached to check a site, the answer comes first:
>   «Fikk ikke svar fra Brønnøysundregistrene» with «Prøv igjen», then
>   the search. The heading «Fikk ikke sjekket …» that said the same is
>   gone.
> - A sole proprietorship names its owner: «Innehaver» in the popup and
>   first under Ledelse in the panel.
> - One way of saying things: every date reads «26. aug. 2026», every
>   search field says «Navn eller org.nr», an org.nr that finds nothing
>   reads «Fant ikke noe selskap med org.nr …», and missing accounts are
>   explained in the register's words instead of «brreg sitt åpne API».
> - Less repetition: the popup's search view drops the line under its
>   heading that repeated the placeholder, the picker's «Eller søk selv»
>   field starts empty instead of holding the site's name, and on a tab
>   with no address the popup shows the logo alone over «Ingen nettside
>   å slå opp».
> - An org.nr that belongs to a branch: the «Avdeling: …» line mutes the
>   part of the branch's name it shares with the parent, as Enheter does.
> - The popup shows the loading outline under the site's name as soon as
>   it opens, instead of a blank strip while it finds the company.
> - The panel's back bar underlines on hover, «Kopier sammendrag» sits
>   at the right edge with or without registry flags before it, and the
>   equity bar's empty part is a hairline grey, not the loading grey.
> - [chrome] Search fields no longer show Chrome's built-in clear «×»,
>   the one control not drawn in the extension's own colours.
>
> ### Fixed
>
> - With auto-sync off, a lookup in the popup could set or clear the
>   toolbar badge of the tab the panel followed before. The badge now
>   marks only the tab whose company is on screen.
> - The focus ring inside a danger verdict is clearly visible; screen
>   readers hear the equity bar's legend; «Endret nylig» keeps its
>   neutral mark next to a merknad; the panel's back navigation no longer
>   leaves an empty landmark.
> - A site whose lookup partly failed could keep a cached direct answer
>   where a complete lookup shows a picker.
> - Short subsidiary keywords no longer match inside longer words (IT in
>   SPIRIT, CARE in SKINCARE), and a site with æ, ø or å in its domain
>   ties to the company that registered it.
> - A failed roles fetch showed as a row that read like data («Roller:
>   Kunne ikke hentes»); Ledelse now says it in a sentence, as Personer
>   does: «Kunne ikke hente roller. Prøv igjen senere.»
> - The panel's loading outline has a Kobling row only when the answer
>   will, so the rows no longer jump when it fills in. A short company
>   (a deleted one's Registrering) no longer scrolls into blank space
>   before you use its tabs.
> - Choosing a company from the picker, a search or the recent list
>   with the keyboard puts focus on the result, and a failed lookup puts
>   it on the error; «Oppdater» in the popup keeps focus on itself.
> - At narrow panel widths a «·» no longer starts a line, a postcode
>   stays with its place, a legal form («AS») or a count is no longer
>   left alone on a line, and «Rapporter feil treff» stays at the right.
>   In the picker, every row's tag sits in the same place.
> - An amount too small for the Økonomi trend's unit («<0,1») reads
>   exactly on hover and to screen readers («12 345 kr»), not rounded.

## Privacy policy (listing sync, only if PRIVACY.md changed)

`PRIVACY.md` reflowed for AMO's field, which keeps every newline and
renders no headings or tables. Sent under `nb-NO`, the add-on's
default locale.

<!-- field: privacy_policy -->
```text
_Last updated: 2026-10-15. Applies to brreg-snap 1.4 and later._

brreg-snap is a browser extension for Firefox and Chrome that shows public information about Norwegian companies from [Brønnøysundregistrene](https://data.brreg.no/) (the Brønnøysund Register Centre). To find the company behind the site you are on, it sends that site's domain name to the register's public API. This page says exactly what is sent, when, and what is kept on your device.

**Summary**

- The extension talks to one service only: `data.brreg.no`, the public API of Brønnøysundregistrene, a Norwegian government agency.
- It sends the domain of the site you look up (for example `dnb.no` when you are on `nettbank.dnb.no`; subdomains are not sent, but on some known hosting platforms, such as `github.io`, the site's own name there is its domain: `firma.github.io`). It never sends the full page address, the page title or cookies, and never page content unless you select text and choose to look it up.
- Nothing goes to the developer or to any other party. There is no developer server, no analytics, no ads and no telemetry.
- Lookups happen when you ask for one. If you turn on the optional «Auto-oppdater» setting, brreg-snap also looks up the page you are on every time you switch tabs or open a new page, as long as a brreg-snap sidebar / side panel is open.

**When data is sent**

The extension contacts `data.brreg.no` only when you:

1. click the brreg-snap toolbar button or press its keyboard shortcut,
2. open the brreg-snap sidebar (Firefox) or side panel (Chrome), by button or keyboard shortcut,
3. choose «Vis i brreg-snap sidebar» or «Slå opp «…» i brreg-snap» in the right-click menu,
4. type in the search box, or click a company, link or button inside the extension, or
5. have turned on «Auto-oppdater». Then every time you switch tabs or open a new page, the page you are on is looked up, as long as a brreg-snap sidebar / side panel is open. The setting covers every window; each open panel follows the tabs of its own window. Closing the panel stops this.

IP addresses (like `192.168.1.10`) and reserved local names are never sent: `localhost`, names without a dot, and endings such as `.local`, `.lokal`, `.internal`, `.intern`, `.lan`, `.home.arpa` and `.priv`. Other names that only work on a private network are looked up like any other site.

**What is sent**

- The site's registrable domain. Subdomains and `www.` are not sent. On some known hosting platforms, such as `github.io`, the site's own name there is kept (`firma.github.io`) — Example: `dnb.no` (on `nettbank.dnb.no`); Why: Finds companies that list that domain as their website
- The main word of that domain, plus Norwegian spellings of it — Example: `elkjop`, `elkjøp` (on `elkjop.no`); Why: Finds companies whose name matches the domain
- An organisation number — Example: `923609016`; Why: Fetches the company's registry entry, roles, sub-units, group structure, recent changes, the latest accounts and the list of filed annual reports. All of it from `data.brreg.no`. The number comes from the page address or title (read on your device), from a search result, from a link in the extension, or from your recent lookups
- Text you type in the search box — Example: `equinor`; Why: Searches the register by company name
- Text you select, only when you choose «Slå opp «…» i brreg-snap» in the right-click menu (at most 100 characters) — Example: `Kiwi Norge`; Why: Searches the register by company name, as if you had typed it. If the selection contains exactly one valid organisation number, only that number is sent; otherwise the text is searched as it is

Never sent: the full page address (path and query string), the page title, page content other than text you select and look up, cookies or login data, or any identifier for you or your browser.

«Rapporter feil treff» does not send anything either. It opens your own mail client with a message to the developer, prefilled with the site's domain, the organisation number shown, how it was matched, and the extension's version and browser. Nothing leaves your device unless you send that mail yourself.

When the extension is first installed it opens one welcome page. That page makes no request and stores nothing; the only browser API it reads is the list of your keyboard shortcuts, to show them.

As with any web request, Brønnøysundregistrene's servers see your IP address and standard browser request headers. Their own terms apply to their API.

**What is stored on your device**

None of this is synced or sent anywhere.

- **Lookup cache** (`storage.session`): register responses keyed by organisation number, and the lookup result for each site you looked up, including a company you picked or rejected for that site. It makes repeat visits instant and spares the API. Entries expire after 24 hours, and the whole cache is cleared when you close the browser.
- **Recent companies** (`storage.session`): the last 5 companies you viewed (name, organisation number, time and, for a bankrupt or deleted company, that status as it stood), shown when the popup or sidebar has nothing else to show. Cleared when you close the browser.
- **One setting** (`storage.local`): on or off for «Auto-oppdater». Kept until you change it.

Removing the extension deletes all of it.

**Permissions**

- `activeTab`: Read the address and title of the current tab when you click the toolbar button, the sidebar button or a right-click menu item, or press a brreg-snap keyboard shortcut. No access to page content.
- `storage`: The cache, recent list and setting above.
- `menus` (Firefox) / `contextMenus` (Chrome): The «Vis i brreg-snap sidebar» and «Slå opp «…» i brreg-snap» right-click items.
- `sidePanel` (Chrome only): Show the details view in Chrome's side panel.
- `https://data.brreg.no/*`: Talk to the register's API. The only site the extension connects to.
- `tabs` (optional, off by default): Requested only when you turn on «Auto-oppdater» and confirm the notice that says what it sends. It lets an open panel read the address and title of the page in front when you switch tabs or open a new page. Turning the setting off gives the permission back. On Firefox you can also remove it in `about:addons`; on Chrome, removing the extension removes it too.

**Store declarations**

- **Firefox** lists «browsing activity» as required data collection, because the domain of the site you look up is sent to Brønnøysundregistrene. It goes only to that public registry, never to the developer.
- **Chrome Web Store** lists the same data as «Web history». brreg-snap's use of information received from Chrome extension APIs adheres to the Chrome Web Store User Data Policy, including the Limited Use requirements. The data is used only to show you the company behind a site. It is not sold, not used for advertising or creditworthiness, and the developer never receives it.

**Source code**

Open source under the MIT License at [github.com/ikkeseb/brreg-snap](https://github.com/ikkeseb/brreg-snap). No third-party code in the extension, no remote code, and a strict Content Security Policy that only allows connections to `data.brreg.no`.

**Contact**

Email [sebastian@nuez.no](mailto:sebastian@nuez.no), or open an issue at [github.com/ikkeseb/brreg-snap/issues](https://github.com/ikkeseb/brreg-snap/issues).
```
